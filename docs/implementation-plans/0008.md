# Plan de implementación: Validar el capítulo con un hook PostToolUse en cuanto se escribe

- Spec de origen: docs/specs/0008/spec.md · Fecha: 2026-09-24 · Estado: Borrador

Correspondencia de requisitos: R1–R11 ↔ RF-01–RF-11 (mismo número) · R12–R17 ↔ RNF-01–RNF-06.
Las decisiones de la spec (`docs/specs/0008/decisions.md`) se citan como «spec D#»; las de este plan, como «D#».

## 1. Resumen

Se añade un segundo hook de proyecto, `PostToolUse`, en `.claude/hooks/validar-capitulo.py`, que ejecuta `novela validar --origen hook` cada vez que el `escritor` o el `editor-estilo` escriben `novelas/<slug>/capitulos/NN.md`, y devuelve los hallazgos al agente con exit 2 dentro de su misma invocación. `novela validar` gana la opción `--origen` para que esas validaciones queden en `harness.log` como `validar-hook NN` y no gasten intentos del procedimiento. Se registra en `.claude/settings.json`, se vigila desde `comprobar-entorno` y se documenta en `docs/validators.md` y `docs/architecture.md`. Así el gate mecánico corre aunque el orquestador se salte un paso, y HAR-04 (`docs/auditoria-entregable.md`) pasa a tener evidencia.

## 4. Decisiones de diseño

Las decisiones de comportamiento son las de la spec (spec D1–D14). Estas son las de implementación.

### D1. Script con funciones puras y `main` fino, como el hook existente
- Alternativas descartadas: un `main` monolítico probado solo como subproceso.
- Motivo: `denegar-escritura-estado.py:85-134` separa `decidir` de `main`. Aquí, `capitulo_de(entrada) -> tuple[str, str, str] | None` (novelas_dir, slug, NN o fuera de alcance), `mensaje_rechazo(ruta_informe, nn) -> str` y `mensaje_fallo(causa) -> str`. Permite probar con `importlib.util` (como `backend/tests/test_hook.py:4`) los casos de spec §9 que no tienen CA y que un subproceso no provoca fácilmente, como el informe ilegible tras un 1.

### D2. `--origen` como `StrEnum` con `typer.Option`
- Alternativas descartadas: `str` con validación a mano; `Literal`.
- Motivo: es el patrón de `export/cmd.py:18,33`. Un valor fuera del enum lo rechaza el parser antes de entrar en el cuerpo de `validar`, así que no se toma el lock, no se abre run y no se escribe `qa/` ni `harness.log` (R7). Que el código sea exactamente 2 lo fija CA-08 al verse en rojo y en verde; no lo he comprobado en ningún test existente del repo.

### D3. Segunda constante y segundo parámetro en `comprobaciones.entorno`
- Alternativas descartadas: convertir `hook_existe: bool` en una lista de hooks ausentes.
- Motivo: cambio mínimo sobre una función pura cuya firma usan tres tests. Se añade `HOOK_VALIDACION = ".claude/hooks/validar-capitulo.py"` y `hook_validacion_existe: bool`, con hallazgo `falta {HOOK_VALIDACION}`, y la cáscara lo calcula igual que `:48`. El código de salida sigue siendo 1, el mismo que para el hook `PreToolUse` ausente (R10).

### D4. Cada documento en el commit de la tarea que lo hace verdad
- Alternativas descartadas: un commit final de documentación (spec T-05 aislada).
- Motivo: `AGENTS.md` § Proceso: modificar documentación exige que la documentación de referencia describa lo que hay, en el mismo commit que el código. `--origen` se documenta con T1.1; el hook, sus filas de §4.17 y §6 y el árbol, con T3.1, que es cuando pasa a ejecutarse; `comprobar-entorno`, con T3.2. T4.1 revisa CA-12 sobre el conjunto.

### D5. Precondición explícita de `novela` en el `PATH` de los tests
- Alternativas descartadas: `pytest.skip` si no resuelve.
- Motivo: un skip dejaría en verde una suite que no prueba el hook (un guardarraíl que falla abierto, `docs/validators.md` §4.4). Un fixture de `test_hook_validacion.py` hace `assert shutil.which("novela")` con un mensaje que manda ejecutar con `uv run pytest` (ver P5).

### D6. `PATH` sin `novela` en CA-05 quitando toda entrada que lo resuelva
- Alternativas descartadas: quitar solo el directorio del venv.
- Motivo: en la máquina de desarrollo también puede estar el `novela` de `uv tool` en `~/.local/bin` (`AGENTS.md` § Proceso: ejecución; F-57). El test filtra las entradas de `PATH` para las que `shutil.which("novela", path=entrada)` no es `None`. El script se lanza con `sys.executable` absoluto, así que no necesita el `PATH`.

### D7. El script reenvía solo stderr propio; nunca la salida de `novela`
- Alternativas descartadas: reenviar stdout/stderr del CLI.
- Motivo: RF-02 exige stdout y stderr vacíos con 0, y RF-03/RNF-04 acotan el mensaje. El subproceso se lanza con `capture_output=True`; con fallo del harness, la causa es una línea compuesta por el script (código de salida, `TimeoutExpired`, ausencia del informe), sin volcar el traceback del CLI.
