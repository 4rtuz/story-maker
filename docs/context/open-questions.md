# Open questions found while restructuring

> Gaps, ambiguities and unstated assumptions found in `docs/suspense-novel-harness.md` while
> splitting it into this context set. **Nothing here has been filled in or guessed.** Each entry
> names what is missing and where the gap is.
>
> This is *not* the specification's own `[OPEN: ...]` register — that lives verbatim in
> `unresolved-decisions.md` (§17), plus the stack risk in `scope.md` (§2).

## Scope

- Things an implementer has to decide because the source does not say.
- Each entry: what is undefined, the source heading and line, and why it matters.
- Grouped by the destination file that carries the surrounding text.
- Load before implementing a section, alongside that section's own file.

---

## Q-01 · `config.json`'s `base` key names are never given

`config-schema.md` (§6.0, lines 675-706) describes `base` in English prose placeholders
(`{ total, target words, word tolerance, ... }`). Only the `poc` profile example (lines 722-736)
shows real Spanish key names, and it covers six groups out of eleven. The literal key names for
`obra`, `entrevista`, `puertas`, `agentes`, `rutas` and most of `ejecucion` are undefined.
**Matters because**: the deep merge in §6.0 is key-exact.

## Q-02 · No stated contents for the `puertas` group

`config-schema.md` (§6.0, line 692) lists `"puertas": { plan, act close, final, continuity block }`
but never says what the values are — booleans that disable a gate, prompts, timeouts. §11 describes
the gates without referring to any configuration.

## Q-03 · The rolling-summary regeneration algorithm is unspecified

`artifacts-state.md` (§6.9, line 939) says the file is "regenerated by deterministic rules, with no
LLM call", and the schema asks for "one 150-word paragraph, produced by concatenating and
compressing the act's chapter lines" (line 946). **How to compress to 150 words deterministically is
not given.** Annex A.5 step 16 marks it deterministic and not delegable (line 1815, plus lines 1822-1825).

## Q-04 · The language-drift detector has no threshold

`failure-modes.md` (§12, "Language drift") defines detection as "proportion of Spanish function
words below a threshold". The threshold, the word list, and the sample size are not given.
`config.json`'s `deriva_idioma` group (§6.0, line 701) declares only `max retries`.

## Q-05 · The scene-hash mechanism is not specified

`evaluation-loop.md` (§9.5) and `failure-modes.md` require comparing "per-scene hash" to detect
altered scenes. The hash function, and whether whitespace/marker lines are normalised before
hashing, are not stated. Annex B.1 P2 requires byte-for-byte storage "because the scene markers and
the hashes of §9.5 depend on it" (line 1859) without defining them.

## Q-06 · Tie-breaking for "best attempt by mean" is undefined

`evaluation-loop.md` (§9.4 point 1) selects "the attempt with the **highest mean**". If two attempts
tie — plausible on a 1-5 integer rubric with three attempts — the rule does not say which wins.

## Q-07 · The interview loop has no gate and no capture mechanism

`architecture.md` (§4.1) and `state-machine.md` (§10) show `INTERVIEW --> INTERVIEW: rounds 1-3`, and
`artifacts-bible.md` (§6.1) says `interview.md` is written "by the runtime (from the Architect and
the author)". But §11 defines only three gates plus the block gate, none of which is the interview,
and Annex B's P4 port is described only in terms of gates. **How the author's answers are collected
and persisted between rounds is not specified.**

## Q-08 · "Validated against their schemas" has no schema format

`gates.md` (§11, Gate 1, `edit` option) says that on resume the hand-edited files "are validated
against their schemas", and §14 phase F2 requires "schema validators". The schemas in §6 are
illustrative Markdown templates with angle-bracket placeholders; no machine-readable form, and no
definition of what counts as a validation failure, is given.

## Q-09 · `.attempts/` naming and git-ignore are implied, never specified

`state-machine.md` (§10.2, line 1300) and `testing.md` (§15.1 checks 3, 5, 6) refer to
`novel/.attempts/01-i0.md` and `01-i1.md`, and require that `.attempts/` never appear in git
history. The naming convention is only ever shown by example, no `.gitignore` artifact is listed in
§6, and the directory itself is missing from the "full tree" (see `conflicts.md` C-06).

## Q-10 · `reports/` file naming for acts 2 and 3

`artifacts-tree.md` (§6, line 646) shows only `reports/act-1.md`. §11 fires Gate 2 three times and
§5.5 produces one report per act. The naming for the other two is inferable but never stated, and
nothing says who writes the file or when.

## Q-11 · Recalibrated probabilities have nowhere to live

`cost-and-quota.md` (§13.1) says the 0.5 / 0.4 / 0.1 probabilities "must be recalibrated after the
3-chapter rehearsal", and `testing.md` (§15.2, "Recalibration") repeats it. No artifact in §6 and no
field in `state.json` (§10.1) holds them, so the recalibrated values have no home.

## Q-12 · Act-boundary detection is not defined for arbitrary profiles

`binding-claude-code.md` (Annex A.5 step 20) says "if N was an act boundary". The act ranges come
from `config.json`'s `actos` array (§6.0), but the spec never states the rule that derives "boundary"
from it, nor what happens if a profile's `actos` ranges do not tile `1..capitulos.total` contiguously.

## Q-13 · Quota accounting cannot see what it is spending

`binding-claude-code.md` (Annex A.6) states plainly that P6 "is the one that fares worst": the
counter in `state.json` counts logical calls while quota is spent in requests, and "the orchestrator
has no direct visibility of how many requests its own loop has consumed". The spec's answer is a
manual dashboard cross-check during §15. **There is no specified behaviour for the case where the
internal counter says there is budget and OpenRouter disagrees**, beyond the generic 429 handling in
§12.

## Q-14 · The novel's word target is stated but never enforced anywhere

`scope.md` (§2) sets 2,000 words ±15%, `agent-writer.md` (§5.2) tells the Writer 1,700-2,300, and
`artifacts-state.md` (§6.11) records `Palabras` on the card. No rubric criterion (§9.1) and no
blocking rule (§8.2) covers length, so a chapter outside the range can still be accepted. Whether
that is intentional is not stated.

## Q-15 · `[OPEN: exact syntax]` for declaring a tool-less subagent

Carried verbatim in `binding-claude-code.md` (Annex A.3): it is unconfirmed whether `tools: []` is
valid frontmatter in the installed Claude Code version. Listed here because it is the one `[OPEN:]`
marker the source leaves outside §17, so it is easy to miss.
